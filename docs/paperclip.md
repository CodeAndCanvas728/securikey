# Paperclip and other unattended agents

Paperclip resolves secrets on its server and puts them in the environment of the `claude` process it starts. Its provider list is fixed, so SecuriKey cannot be a provider; instead it learns the values Paperclip injects, can seed Paperclip's secrets, and fails closed when nobody is there to unlock a keychain. Set these in the agent's `adapterConfig.env`:

| Variable | What it does |
|---|---|
| `SECURIKEY_WATCH_ENV=A_TOKEN,B_KEY` | The hooks redact these variables' values (8 characters or more, plus their base64 and URL forms) as `[securikey:env:A_TOKEN]`, and deny a tool call that carries one. Without it, `env` or `echo $A_TOKEN` shows a Paperclip-held value to the model. A listed variable that is unset or too short is reported by its position in the list, never skipped silently and never printed (an entry can be a pasted value). Do not list a common variable such as `HOME`: its value would be redacted everywhere. |
| `SECURIKEY_SERVICE=securikey-client` | The keychain item this agent uses, one per org. The hooks, `skey run`, `warm`, `sync` and `rotate` all honour it, and a process with its own service does not read the shared pre-3.0.0 item, so another org's values are neither found nor redacted (`skey migrate` runs on the default service only, for the same reason). Create them with `SECURIKEY_SERVICE=securikey-client skey add <name>`. |
| `SECURIKEY_HEADLESS=1` | Nobody can read a warning or answer the macOS keychain prompt. A keychain that cannot be read in 20 s (`SECURIKEY_HEADLESS_TIMEOUT`) makes `warm` exit 1 with the reason on stderr, and the tool and prompt hooks deny, block or replace the output instead of dropping to pattern checks. |

Install SecuriKey at user scope: when Paperclip runs Claude Code with `--setting-sources user`, a project-scope install is not loaded. Before the first run, check the setup as the user the daemon runs as:

```bash
skey doctor --headless     # uv on PATH, keychain readable, Claude Code >= 2.1.295, user-scope install, watched variables set
```

**Seeding Paperclip.** `skey sync paperclip` creates each keychain name as a company secret. The settings come from the environment and the keychain, never from arguments: `SECURIKEY_PAPERCLIP_URL`, `SECURIKEY_PAPERCLIP_COMPANY`, and a board token stored with `skey add paperclip_token` (or `SECURIKEY_PAPERCLIP_TOKEN`). Plain `http://` is accepted for this machine only, and a redirect is never followed (the token would go with it). Both commands are for you, in your own terminal, because the server address can be set on the same command line. Two things enforce it: the commands refuse to run unless stdin is a terminal (and `SECURIKEY_HEADLESS` is unset), and the pre-hook denies any Bash call that names `skey sync` or `skey rotate`, also nested, quoted, glued to a separator or behind an expansion (a commit message that mentions them is denied too). The hook reads shell text, which is never complete, and a process that opens its own pseudo-terminal is outside what the terminal check stops: these are layers, not a sandbox. It prints names, actions and ids, never values; a name Paperclip already has is kept unless you pass `--update` (a new version), and `--only a,b` and `--dry-run` narrow it. `skey rotate <name>` stores a new value (hidden prompt), keeps the old one redacted for `--keep-days` (default 7) and updates the Paperclip secret if it exists there.

**Pulling from Paperclip.** Prefer plain env bindings with `SECURIKEY_WATCH_ENV`. Where an agent needs a value only on demand, `skey run --env-from-paperclip VAR=key -- <command>` fetches it with the run's own token (`PAPERCLIP_API_URL`, `PAPERCLIP_API_KEY`), registers it for redaction for 24 hours before the command starts, and passes it as `VAR`.

**Audit.** `skey run`, `sync` and `rotate` append one line to `~/.cache/securikey/audit-<service>.log` (mode `0600`): time, service, command, secret names, variable names, the command's basename and its parent process. Never a value or an argument. Reconcile it with Paperclip's `secret_access_events`.

**Hook cost.** `python bench/hook_cost.py` measures both tool hooks. On an Apple-silicon Mac (uv 0.11, 100 runs, empty store), the check itself takes about 1 ms; the end-to-end call, which is almost all `uv` and interpreter start-up, has p50 96 ms and p95 107 ms (pre) and 119 ms (post). Each tool call pays for both. The budget is p95 under 150 ms per hook; the script exits 1 when it is exceeded.

**Limits that remain.** A terminal is not proof of a person, and the hook cannot read every shell spelling (brace lists, `${IFS}` and expansions are handled; an encoded command is not). An agent with a shell can already hand any stored value to a command it chooses (`skey run --env X=name -- curl ...`), so SecuriKey keeps values out of the model's context; it does not stop a hostile agent from sending them elsewhere. For that, bind the secret where the agent cannot reach it, or do not give the agent a shell. `skey run --env-from-paperclip` sends the run's own token to `PAPERCLIP_API_URL`, which a command can set inline, so a hostile command can send that token to another host (the token is the agent's own and already in its environment; use plain env bindings with `SECURIKEY_WATCH_ENV` where that matters). Claude Code's local transcript records tool output before the hook rewrites it, so `~/.claude` can still hold an injected value on disk. Paperclip's own run log and issue comments are not covered by these hooks. A value shorter than 8 characters is never redacted.
